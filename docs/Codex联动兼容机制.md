# Codex 更新后，草鱼怎样尽量继续工作

此说明针对 0.1.8.2 源码。旧的 0.1.8.1 发行包不包含这些改进。

## 一句话说明

任务连接自动寻找可用入口，任务界面尽量沿用本机已经验证的官方组件。因此，Codex 更换安装目录、资源文件名或任务入口时，不必一概重新安装草鱼。它不是对所有未知未来版本的永久兼容承诺。

## 任务连接

- 只连接已经运行的 Windows Codex 桌面程序，不启动第二套 app-server 或 Electron。
- 支持 codex-app-tools-* 入口，并保留 codex-browser-use-* 旧入口兼容。环境变量只能提供这些本地入口族的提示，不接受远程管道或任意服务。
- 每次请求先验证管道的实际服务进程属于受支持的 Codex MSIX 安装。找到一个名字相似的入口，并不等于可信连接。
- 发现入口后，检查列出任务、读取对话、回复和打开对话四项能力，并验证当前用户已经存在的本地对话；不依赖作者的对话标识。
- 最多检查 32 个候选入口、每个入口最多 4 个已有本地对话。整个发现过程共用约 12 秒的 I/O 等待预算，而不是每个候选都等待 12 秒。
- 连接失效后，既有后台退避重试会重新发现入口；正常连接时不反复扫描入口。用户也可以点击重试。不对发送消息做自动重试。
- 暂时超时、尚无本地对话、找不到入口、缺少任务能力和未知列表格式分别显示原因。确实不兼容时提示更新草鱼，而非一直泛称“连接恢复中”。

## 官方任务界面

草鱼自己的宿主页使用固定的组件名称。具体官方文件名、导出符号、依赖文件哈希和样式顺序由发行源码中的可信清单描述，普通用户不用配置。

1. 优先读取“上次成功挂载”的本机缓存提示；提示本身不作为信任依据。
2. 用程序附带的适配清单逐文件重新校验缓存，拒绝缺失、篡改、未列出的 vendor 文件以及链接目录。旧版按安装包路径命名的完整缓存也可以继续用。
3. 只使用随草鱼安装的宿主页和适配桥，不执行缓存里来源不明的旧宿主代码。
4. 没有可用缓存时，才从运行中的 Codex 只读提取已适配版本。逐文件校验并写入暂存目录，全部成功后再启用；失败不覆盖原缓存。
5. 界面实际成功挂载后，才记录为优先使用的缓存。

缓存身份由可信组件清单决定，不再由 Codex 安装路径、资源包大小或文件时间决定。继续使用旧界面，意味着保留已经认可的交互，不意味着自动追随新版 Codex 的全部外观变化。

已适配的官方组件来源：Windows Codex MSIX **26.1007.9446.0**、**26.1013.3656.0**。清单内仅包含文件名、哈希、少量导出绑定等适配信息，仓库和安装包不含提取出的官方 vendor JS/CSS。缓存始终只保存在对应用户电脑上。

## 什么情况仍需要更新草鱼

- Codex 改变任务协议、工具名称、权限或返回格式，现有能力检查不能通过。
- 首次安装的电脑只有一个尚未适配的新 Codex，也没有旧的有效界面缓存。
- 用户清理或修改了所有可用缓存，而当前 Codex 的组件又不在已适配范围。

上述情况不会通过关闭完整性校验、修改 Codex 安装包、复制账号配置或下载未知可执行脚本来“强行兼容”。喝水、吃饭、自定义日程和猫咪动画仍可独立使用。

## 验证方式和未覆盖范围

- 真实运行的 Codex：只读验证自动发现、任务列表和读取已有本地对话，不发送真实消息、不新建任务、不做真实跳转。
- 隔离管道和合成资源包：验证新旧入口、能力检查、服务进程身份、未知接口格式、超时、缓存跨版本复用、损坏拒绝、暂存失败和旧缓存迁移。
- 不可见嵌入式 WebView：分别验证当前版本的全新提取和旧版本缓存的独立加载，检查回复框、中文输入法 Enter、草稿镜像及重建后的恢复。不可见测试用计时器驱动动画回调，只验证状态逻辑，不冒充可见桌面的动画时序验收。
- 保留原有收起后 15 秒温缓存策略，没有新增常驻进程。此次不是另一轮内存瘦身，不能据此宣传特定的内存下降幅度。
- 未进行第二台实体电脑的端到端验收，也未测试所有未知 Codex 版本。普通使用者不应把自动化检查理解为永久兼容保证。

仅编译和隔离测试不会替换正在运行的安装版本。安装、提交、推送或发布新发行包另行确认。
