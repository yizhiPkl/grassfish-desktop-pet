# 更新发布流程（维护者）

## 两种签名不是一回事

草鱼 0.1.9.0 内置一把公开的验证钥匙，用于确认更新说明由本项目维护者签发；说明中写明版本、安装包大小和 SHA-256。对应的私钥放在工程外，不提交 Git、不随安装包发布。请离线安全备份；丢失后不能继续给已安装客户端签发可信更新。不要临时生成另一把私钥来签后续版本。

这不是 Windows Authenticode 代码签名。目前安装程序仍可能显示未知发布者或 SmartScreen 提示，不能宣传已获得微软发布者认证。

## 本地准备

1. 修改 AssemblyInfo.cs 中的四段版本号，例如 0.1.9.1。关于页面与安装器自动读它，不再手写另一个版本。
2. 先完成隔离测试，再用 build-installer.ps1 在新的输出目录制作干净的安装程序。
3. 准备 UTF-8 的纯文字更新说明，然后执行以下脚本。私钥必须放在仓库外，脚本检查它与客户端公钥相符。

~~~powershell
./tools/create-update-manifest.ps1 -Installer '输出目录/GrassFish-Setup-0.1.9.1-win-x64.exe' -SigningKey '仓库外的私钥.xml' -NotesFile '更新说明.txt' -OutputDirectory '输出目录'
~~~

脚本只写本地文件，不会上传。不要在生成签名后修改 JSON、安装包，或重建同版本安装包后继续使用旧签名。可用 DesktopKitten.exe --verify-update-package 检查输出目录和报告文件路径，对照生产内置公钥校验；此模式不安装。

## 经项目所有者明确同意后才发布

GitHub 正式 Release 的标签必须为 v 加四段版本号，例如 v0.1.9.1。上传三份配套文件：

- GrassFish-Setup-0.1.9.1-win-x64.exe
- grassfish-update.json
- grassfish-update.sig

不要标记为 pre-release；草稿对普通用户不可见。下载地址必须属于本项目固定仓库的 Release，不支持任意镜像或可执行远程适配脚本。便携 ZIP 和校验单可额外上传，但不参与内置更新。公开仓库、Git 推送、发布 Release 都是不同操作，不能因为用户批准本地开发就擅自进行。

## 运行边界与失败处理

- 默认启动约30秒后检查，24小时内不重复自动检查；手动检查不受此限制。关闭自动检查不影响手动按钮。用户跳过的版本不自动弹窗。
- 没有常驻更新器；只有用户确认后下载，安装前启动程序自身的临时副本。下载最多256MB，有读写超时、15分钟传输上限及 HTTPS 官方主机限制，不带账号令牌、Cookie 或认证文件。
- 更新器不强制结束草鱼或 Codex。安装前检查草稿、发送中消息和小窝未保存编辑；收好任务渲染器后再次检查，再等父进程正常退出。父进程没有退出则不安装。
- 沿用现有安装目录，保留独立用户数据和任务组件缓存。不同于已有安装登记的另一个便携目录，须手动安装以免覆盖其他副本。
- 只备份草鱼已知应用文件以及 assets、third-party，不会把整个桌面或其他项目复制进备份。限制文件数量与总大小、拒绝链接和越界路径。安装失败尝试恢复备份及相关版本登记，不承诺完整事务回滚；恢复失败保留备份并给出提示。
- 保留最近两份已完成更新目录；超过14天的更旧成功/取消/下载失败目录会清理。失败安装与未完成备份不自动删除，供手动恢复。不要把整个 updates 目录上传。
- 下载文件的签名/大小/摘要必须一致；重定向也须在允许的 HTTPS 主机内。无签名或签名不符的新版不提供安装。GitHub 不可达时日程仍可用。
- 0.1.8.x 没有此更新器，用户需手动安装一次 0.1.9.0 或更高版本。首次上线后还需用两份真实发布版本验收下载、正常退出、安装和重启；本地假安装器恢复测试不能替代这一环节。
